1. Документація пояснює призначення й використання коду. Документаційні коментарі мають спеціальний формат і обробляються інструментами, а звичайні лише пояснюють код читачеві.

2. CS1591 виникає, коли ввімкнено генерування XML-документації, але публічний тип або його доступний член не має документаційного коментаря.

3. CS1591 доречно приглушувати для згенерованого коду або частин, які не документують. Локально: #pragma warning disable CS1591 та #pragma warning restore CS1591. Для проєкту: <NoWarn>$(NoWarn);1591</NoWarn>. Публічний API краще документувати.

4. У PropertyGroup файлу .csproj додати: <GenerateDocumentationFile>true</GenerateDocumentationFile>.

5. Якщо немає опису ендпойнта: додати XML-коментарі й підключити XML-файл API через IncludeXmlComments у AddSwaggerGen у Program.cs. Для Minimal API також застосовують WithSummary і WithDescription.

6. Якщо немає опису схеми: додати XML-коментарі до DTO та їхніх полів, увімкнути GenerateDocumentationFile у проєкті DTO й підключити його XML-файл через IncludeXmlComments у Program.cs.

7. JSDoc — формат документування JavaScript у блоках /** ... */. Основні теги: @description — опис, @function — функція, @param — параметр, @returns — результат, @example — приклад.

8. C# використовує XML-теги в коментарях /// та генерує XML-файл компілятором. JavaScript використовує блоки JSDoc із @тегами; їх обробляють JSDoc та редактори. У C# типи задані в коді, а в JSDoc їх можна додатково вказувати в коментарях.
