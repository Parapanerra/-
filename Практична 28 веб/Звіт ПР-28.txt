Практична робота 28
Встановлення та налаштування Docker контейнера вебзастосунку

Мета: запустити PostService у Linux-контейнерах Docker із публікацією порту та збереженням даних.

Хід роботи
1. Використано вебзастосунок ПР-49–50 з оформленням із коміту https://github.com/Parapanerra/-/commit/12cdd03.
2. Встановлено Docker Desktop, увімкнено Virtual Machine Platform і WSL, перезавантажено Windows та оновлено WSL до 3.0.3.
3. Виконано docker run hello-world — отримано Hello from Docker.
4. Завантажено BusyBox, запущено echo, видалено тестовий контейнер. Видалено та повторно завантажено образ BusyBox.
5. Створено Dockerfile для Nginx, Dockerfile.api для .NET 10 і compose.yaml. Порт 8080 комп’ютера зіставлено з портом 80 Nginx. Запити /postings передаються до API через внутрішню мережу Docker.
6. Для SQLite створено том postings-data. Початкова база копіюється лише під час першого запуску.
7. До packages додано оригінальні NuGet-пакети: HTTPS-з’єднання з NuGet усередині контейнера не проходило перевірку сертифіката. Перевірку HTTPS не вимикали. Успадкована залежність SQLitePCLRaw.lib.e_sqlite3 2.1.10 має попередження NuGet про відому вразливість.
8. Виконано docker compose up -d --build. Обидва контейнери запущено.
9. Сайт відкрито на http://localhost:8080. Перевірено список із 7 відправлень, форму редагування та повідомлення про порожні обов’язкові поля.
10. API повертає HTTP 200. На окремому тимчасовому записі успішно перевірено POST, PUT і DELETE; тестовий запис видалено.
11. nginx -t підтвердив правильність конфігурації. Після docker compose up -d --force-recreate дані збережено завдяки тому.

Підтвердження
У screenshots збережено скриншоти сайту, списку, створення, редагування та перевірки помилок.
У verification збережено списки образів і контейнерів, журнали та результати перевірок CRUD і збереження даних.
Автоматичне захоплення вікна Docker Desktop завершилося тайм-аутом. Скриншоти Images і Containers потрібно зробити вручну.

Оновлення сайту: docker compose up -d --build --force-recreate
Зупинка без видалення даних: docker compose down

Висновок
PostService ПР-49–50 працює у двох Linux-контейнерах Docker. Сайт доступний на localhost:8080, API працює, база SQLite зберігається в окремому томі.

Відповіді на запитання для самоконтролю
1. Віртуальна машина має власну ОС і ядро, а контейнер використовує ядро середовища Docker та потребує менше ресурсів.
2. Docker-хост — комп’ютер або віртуальна машина, на якій працює Docker Engine.
3. Зупинити й видалити всі контейнери цього образу, потім виконати docker image rm <image_id>.
4. Image — шаблон; container — його екземпляр; volume — незалежне сховище даних.
5. docker build -t my-static-website .
6. CMD задає команду запуску програми в контейнері.
